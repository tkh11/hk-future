# Аудит сайта HEISSKRAFT — 28 октября 2026

## Результат

Исправлены жизненный цикл главной галереи, синхронизация её таймлайнов, действия формы на страницах-заглушках, возврат клавиатурного фокуса и недостаточный контраст нескольких элементов. При проверке CMS обнаружена и исправлена ошибка генерации `sitemap.xml`.

Общий вердикт для коммерческого запуска: **DO NOT SHIP**. Это связано с перечисленными ниже незавершёнными функциями и открытым предупреждением зависимостей. Исправления интерфейса можно проверять локально. Аудит не является утверждением об отсутствии любых возможных ошибок.

## Открытые вопросы с приоритетами

### P1 — до запуска сайта для клиентов

1. **Форма остаётся демонстрационной.** Тест подтверждает интерфейс и сообщение успеха, но не доставку заявки. Нужны серверная отправка, обработка отказов и проверка реальной доставки.
2. **Пять ссылок ведут на отсутствующие страницы:** `/privacy`, `/personal-data`, `/about`, `/docs`, `/requisites`. Они найдены в действующей навигации и отвечают 404. Не подменены пустыми заглушками, чтобы не скрывать незавершённость.

### P2 — зависимость Payload требует отдельного решения

`npm audit` обнаружил **одну первичную уязвимость**, отражённую в девяти пакетах цепочки: `deepmerge` и зависимые пакеты Payload. Это не девять независимых атак. [GHSA-gcqx-w48m-w2h4 / CVE-2026-93753](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) описывает возможность подменить прототип возвращаемого объекта при слиянии недоверенных данных. Advisory обновлён 27 октября; серьёзность low, исправленная версия на момент проверки не указана.

В коде проекта прямых вызовов `deepMerge` не найдено; зависимость используется внутри Payload. Это **не доказывает отсутствие уязвимого пути**. Эксплуатация через публичные маршруты HEISSKRAFT данным аудитом не подтверждена. Следующий шаг — адресная проверка достижимости в используемых операциях Payload и совместимое исправление после появления подтверждённого решения. Не выполнены принудительное понижение зависимости или `npm audit fix --force`, не добавлено исключение, скрывающее предупреждение. Проверка зависимостей намеренно остаётся красной; исходный результат сохранён в `.ecc/audit/dependencies.json`.

### P3 — незавершённые функции и технический долг

- `/projects`, `/warranty`, `/selection/pumps`, `/selection/pipelines` — действующие страницы-заглушки. Их содержимое и подбор оборудования ещё предстоит реализовать.
- 13 предупреждений ESLint про `<img>` требуют адресной оценки загрузки изображений; они не означают, что эти изображения сломаны.
- Реальный публичный домен, production-хостинг и работа внешних сервисов не подтверждаются localhost-проверкой.

## Границы достоверности

- Автоматическая проверка возврата на вкладку управляет Page Visibility API. В используемом автоматизированном Chrome настоящие переключения вкладок сохраняли `visibilityState=visible`; поэтому отдельная проверка нативного фонового режима этого браузера **не подтверждена**. В in-app браузере визуально проверено наличие изображения третьего слайда после исправления. Точный исходный белый кадр со скриншота отдельно воспроизвести не удалось; четыре дефектных сценария жизненного цикла подтверждены тестами до исправления.
- Это не полный тест Safari, Firefox и физических iOS/Android-устройств. Аппаратное декодирование после сна компьютера требует отдельного прогона на этих устройствах.
- Нет утверждения о пиксельном совпадении со старой версией: утверждённого эталона визуальной регрессии не было. Снимки текущих страниц сохранены.
- Проверки WebGL подтверждают функциональность, а не FPS пользовательской видеокарты. Полный нагрузочный тест, профилирование утечек памяти и пять холодных замеров Core Web Vitals в этот аудит не включены.
- В автоматических сценариях iframe Яндекс Карт заменён локальным ответом; доступность самого сервиса не проверялась. Письма и сообщения внешним адресатам не отправлялись.

## Воспроизведение

```sh
npm run typecheck
npm run lint
npm run test
CMS_ENABLED=true npm run build:production
CMS_ENABLED=true PLAYWRIGHT_CHANNEL=chrome npm run test:e2e
npm run cms:test
PLAYWRIGHT_CHANNEL=chrome npm run test:cms:e2e
npm run build:export
npm run test:assets
npm run audit:dependencies
```

Публичные E2E и изолированные CMS E2E по умолчанию используют порт 3100, поэтому команды запускаются последовательно. Основной `npm run dev` на порту 3000 можно оставить работающим. Для экспортированных страниц передать `E2E_EXPORT=true E2E_BASE_PATH=/hk-future` в `test:e2e`.

Сырые результаты обхода и снимки: `test-results/site-audit-2026-10-28/`. Они локальные и исключены из Git; вывод аудита зависимостей и этот отчёт сохраняются в проекте.
