# HEISSKRAFT

Next.js 16.4.2, React 19, Payload CMS 3.92 и TypeScript strict.
Существующий дизайн описан в [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).
Выполненные работы, результаты проверок и границы локального этапа CMS —
в [отчёте о подключении](docs/CMS_IMPLEMENTATION_REPORT.md).

## Локальный запуск

Node 24.22.1 и npm 11.19.0; версия Node закреплена в `.nvmrc`.

```sh
nvm use
npm ci
CMS_ENABLED=false npm run dev
```

Сайт: http://localhost:3000. Это запуск с локальным содержимым без CMS.
Не запускайте несколько dev-серверов в одной папке сборки.

## Локальная CMS

Публичная библиотека `/docs` показывает опубликованные PDF из «Документов каталога»,
без дублей одного файла. Обложки загружаются отдельно; PDF — только после открытия
предпросмотра или скачивания. Черновики документов и файлов недоступны посетителям.

После добавления новых PDF выполните `npm run cms:document-covers`. Команда требует
Poppler (`pdftoppm` в PATH или путь в `PDFTOPPM_BIN`) и локальные файлы медиатеки.
Она создаёт WebP первой страницы размером до 800 px и назначает обложку документу;
повторный запуск пропускает готовые обложки. Исходные PDF и старые изображения
сохраняются, прежние связи записываются в `.local/document-covers/covers-*.json`.
При использовании S3 обложки следует готовить в среде с локальной копией медиатеки.
В статическом демо без CMS библиотека отображает состояние без документов.

«Архив дополнительных материалов» у товаров доступен только сотрудникам в CMS;
он не выводится и не запрашивается страницами товаров. После проверки 30.10.2026
удалены 44 старые обложки, заменённые превью первых страниц PDF. Сканы документов,
видео и внешние ссылки сохранены. Список проверенных файлов —
`src/cms/import/obsolete-resource-covers.json`; повторный импорт их пропускает.
Проверка очистки: `node --env-file=.env.local scripts/cms/cleanup-resource-covers.mjs`.
Режим `--apply` разрешён только для локальной базы и локальных файлов: проверяет
использование, сохраняет резервную копию в `.local/resource-cleanup/`, затем удаляет
только подтверждённые обложки. Резервные копии не входят в Git и публикацию сайта.

Установите PostgreSQL 17. Инициализатор запускает отдельный кластер на
`127.0.0.1:5433`; `PG_BIN` задаёт путь к его CLI, если он отличается от
`/opt/homebrew/opt/postgresql@17/bin`.

```sh
nvm use
npm ci
npm run cms:local:init
npm run cms:migrate
npm run cms:bootstrap
npm run cms:seed
npm run dev
```

Панель: http://localhost:3000/admin. Первоначальная локальная учётная запись
сохранена в приватном `.local/admin-access.txt`; секреты среды — в `.env.local`.
Эти файлы, загрузки, база и резервные копии не попадают в Git. Инициализатор
не заменяет уже существующие секреты, seed не перезаписывает редакторские правки.
Схема меняется миграциями; автоматическое изменение схемы через schema push
отключено.

[Инструкция редактора](docs/cms-editor-guide.md) описывает роли, блоки, медиа,
импорт CSV/XLSX и публикацию. [Развёртывание и восстановление](docs/cms-deployment.md)
содержит команды Docker Compose, параметры PostgreSQL/S3, требования к
HTTPS и шлюзу доступа, резервное копирование и проверку восстановления.

Серверная CMS читает опубликованный контент из PostgreSQL, а черновики показывает
только авторизованным редакторам. `npm run build:export` создаёт **фиксированное
демо GitHub Pages из локального контента**: CMS, `/admin`, API, новые товарные
страницы и аналитика в нём отключены. Публикация в CMS не обновляет Pages.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm test -- --coverage
npm run audit:dependencies
CMS_ENABLED=false npm run build:production
npx playwright install chromium
CMS_ENABLED=false npm run test:e2e
npm run build:export
npm run test:assets
E2E_EXPORT=true E2E_BASE_PATH=/hk-future npm run test:e2e
```

Для серверной CMS после локальной инициализации и миграций:

```sh
npm run cms:test
CMS_ENABLED=true CMS_SERVER_URL=http://localhost:3100 NEXT_PUBLIC_SITE_URL=http://localhost:3100 npm run build:production
PLAYWRIGHT_CHANNEL=chrome npm run test:cms:e2e
```

Интеграционные CMS-проверки создают отдельные временные базы на локальном
PostgreSQL; рабочую базу они не используют как тестовую. Для PostgreSQL нужен
пользователь с правом создавать временные базы. Запускайте тяжёлые сборки и
браузерные проверки последовательно.

`test:cms:e2e` сам создаёт временную БД `hk_test_admin_*`, применяет миграции,
загружает исходный контент и создаёт одноразовые учётные записи. Он запускает
свой production-сервер на свободном порту 3100, использует отдельную временную
папку загрузок и удаляет их после проверки. Рабочая БД и её файлы не меняются.
Не запускайте другой сервер на 3100 перед этой командой. PostgreSQL-пользователю
нужно право создавать тестовые базы. Прямой запуск Playwright CMS без маркера
изолированной среды отклоняется. Обычный `test:e2e` исключает CMS-сценарии.
Traces, видео и автоматические снимки ошибок выключены. Для иллюстраций
инструкции можно явно задать `CMS_E2E_CAPTURE=true`: выбранные экраны без формы
входа сохранятся в приватную `.local/qa` (не публикуются в CI).

Для установленного Google Chrome: `PLAYWRIGHT_CHANNEL=chrome npm run test:e2e`. Playwright сам поднимает production-сервер на порту 3100 и проверяет desktop 1440×900 и mobile 390×844. Обычные проверки запускаются с reduced motion; отдельные видео-сценарии включают движение. Отчёт — `playwright-report/index.html`, ошибки и traces — `test-results/`. Проверки WebGL в headless подтверждают функциональность, но не FPS пользовательского устройства.

Для страниц импортированных товаров: после сборки с включённой CMS запустите `E2E_CMS_CONTENT=true PLAYWRIGHT_CHANNEL=chrome npm run test:e2e -- product-page.spec.ts`. Проверки используют локальный CorrugatedPipe: вкладки и сохранение фильтров, предпросмотр PDF, две колонки документов на мобильном экране и предзаполнение заявки. Без этого флага сценарии пропускаются, поскольку в статической демоверсии нет CMS-товаров. Краткий текст первого блока берётся из поля `summary`, при его отсутствии — из начала существующего описания; обложки и PDF подключаются через опубликованные `catalogDocuments`. Общий просмотрщик документов используется на странице товара и в `/docs`.

`npm run build` / `npm start` — стандартные команды Next. `build:production` и `start:production` используют `.next-production`, не затрагивая `.next` работающего dev-сервера. `build:export` собирает проект во временной изолированной копии и сохраняет готовый сайт в `out/`. Это необходимо: при `output: export` параметр Next `distDir` меняет папку экспорта, а промежуточная сборка всё равно использует `.next`. Не запускайте ручной `GITHUB_PAGES=true next build` рядом с работающим dev-сервером.

GitHub Actions выполняет типизацию, lint, unit-тесты, аудит, серверную сборку
без CMS и статический экспорт с браузерными сценариями. Отдельное CMS-задание
поднимает временный PostgreSQL 17, применяет миграции, выполняет bootstrap,
seed, интеграционные проверки, CMS-сборку, CMS E2E и backup/restore. Публикация Pages
возможна только из `main` после всех проверок; PR-проверки не имеют прав
публикации и не получают серверные секреты.

## Структура

- `src/app/(frontend)` — публичные маршруты, метаданные и композиция страниц.
- `src/app/(payload)` — административная панель, API, preview и импорт.
- `src/cms` — схема CMS, права доступа, блоки страниц, импорт, аналитика и миграции; `payload.config.ts` — серверная конфигурация.
- `src/content/cms-adapter.ts` — проверенные публичные данные и локальное содержимое при отключённой CMS; серверные объекты Payload не передаются клиенту целиком.
- `src/content` — типизированные локальные данные каталога, контактов, статей и страниц решений; `src/data/articles.json` — исходные статьи.
- `src/lib/catalog.ts` — чистые функции поиска и обхода переданных данных, без встроенного каталога.
- `src/sections` — компоненты конкретных страниц; интерактивные островки получают данные через props.
- `src/components/ui/RevealBlock.tsx` — появление при прокрутке, без ожидания изображений и без скрытия текста в HTML без JavaScript.
- `ViewportMount` — загрузка тяжёлых сцен при появлении в экране; заглушка занимает только область модели.
- `ViewportImage` — большие товарные баннеры загружаются в своём viewport, сохраняют пропорции и доступны через `noscript` без JavaScript.
- `src/components/models/ModelHelp` — общий интерфейс инструкций моделей.
- `createRetryableModel` — локальная граница ошибки динамического viewer; повторная попытка после сетевого отказа не перезагружает страницу. Ошибки GLB/WebGL обрабатываются внутри сцены. Описания остаются доступны.
- `src/lib/model-loader.ts` — локальный Meshopt, отмена/таймаут загрузки и освобождение ресурсов.
- `public` — изображения, видео, модели, локальные шрифты и декодеры. Пути файлов в компонентах проходят через `publicPath` для поддержки `/hk-future`.

Локальная CMS, PostgreSQL, preview и обновление публичного контента после
публикации подключены. Секреты и SDK остаются на сервере. Внешняя инфраструктура
в РФ, S3, DNS, TLS, VPN/MFA-шлюз и Метрика требуют отдельных доступов и пока
не развёрнуты. Описания продукции отделены от координат, камер и идентификаторов
3D-сцен. Геометрия и поведение моделей не редактируются в CMS.

## Воспроизводимые измерения и медиа

```sh
PLAYWRIGHT_CHANNEL=chrome BENCHMARK_URL=http://localhost:3100 BENCHMARK_LABEL=current npm run benchmark
node scripts/compare-benchmarks.mjs
PLAYWRIGHT_CHANNEL=chrome BASELINE_URL=http://localhost:3101 node scripts/benchmark-paired.mjs
PLAYWRIGHT_CHANNEL=chrome BENCHMARK_URL=http://localhost:3100 BENCHMARK_LABEL=current node scripts/benchmark-models.mjs
```

Каждый вариант проверяется отдельно: пять холодных контекстов, одинаковый Chrome/компьютер, desktop и mobile (4 Мбит/с, 150 мс, CPU ×4). Не запускайте параллельно сборки, кодирование видео или другие браузерные проверки. Результаты — `.ecc/benchmarks/`. Сравниваются медиана и диапазон; превышение 10% требует разбора. Первые 12 секунд загрузки и загрузка моделей после прокрутки измеряются отдельно. Это лабораторные наблюдения, а не полевые Core Web Vitals.

`benchmark-paired.mjs` нужен только при отклонениях полного сравнения: исходная сборка должна работать отдельно на `BASELINE_URL`, текущая — на `BENCHMARK_URL` (по умолчанию 3100). Он выполняет пять чередующихся холодных пар для каждого отмеченного маршрута и профиля. Исходные результаты и порог 10% сохраняются; повторный контроль не подменяет полную серию.

Оптимизированные медиа уже находятся в `public`; кодирование не выполняется при сборке/CI. `scripts/optimize-videos.mjs` создаёт облегчённые MP4. Команда `PLAYWRIGHT_CHANNEL=chrome node scripts/generate-video-posters.mjs` обновляет четыре постера по первому кадру видео с запущенного сайта (`POSTER_BASE_URL`, по умолчанию порт 3100). Постеры снимаются через браузер, чтобы сохранить цветовое преобразование BT.709. `scripts/verify-videos.mjs <исходная-копия-проекта>` проверяет длительность, FPS, пропорции и SSIM. Исходные файлы доступны в Git/сохранённой копии; не перекодируйте уже оптимизированное видео повторно.

`scripts/compress-models.mjs` использует lossless EXT_meshopt_compression: без квантования, изменения топологии, имён, материалов и transforms. Режим `--report <папка-исходных-GLB>` повторно декодирует и сравнивает каждый bufferView. Камеры и выбор элементов дополнительно проверяются в браузере. В итоговом наборе сжаты только ЦОД и FireOff: для здания и этажа преобразование отклонено, поскольку реальная передача после HTTP gzip выросла. Не применяйте сжатие ко всем ресурсам автоматически, проверяйте сетевые и временные показатели каждого кандидата.

## Известные ограничения

- Форма заявки демонстрационная. Успешный тест и экран подтверждения **не означают доставку заявки**.
- `/privacy`, `/personal-data`, `/about`, `/docs`, `/requisites` пока не реализованы. Проверки отмечают эти известные ссылки отдельно.
- Проверка зависимостей 26 октября 2026 года завершилась с 0 уязвимостей. [FOUNDATION_REPORT.md](docs/FOUNDATION_REPORT.md) описывает исторический базовый аудит; прежняя находка `braces` не является текущим результатом. Для актуальной проверки запускайте `npm run audit:dependencies`.
- Существующие предупреждения lint о `<img>` перечисляются явно; они не подавляются массово.
- Внешнее развёртывание CMS, подключение приватного S3 и Метрики, реальная отправка заявок, финальные юридические тексты, CSP/HTTP-заголовки хостинга и коммерческая публикация требуют настройки инфраструктуры. Docker-конфигурация подготовлена, но контейнеры на этой машине не запускались: Docker не установлен.
