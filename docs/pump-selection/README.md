# Подбор насосов HEISSKRAFT

Состояние на 16 ноября 2026 г. В Studio опубликованы 248 карточек HIP.

## Данные и управление

Источник подбора — опубликованные записи `pump-selection-records`. Они самостоятельны и не зависят от ассортимента или вариантов товаров. Папки и карточки управляются в Studio без списков артикулов в коде.

Иерархия — «Программа подбора насосов» → серия → типоразмер → исполнение → карточка с артикулом. Пример — HIP → HIP 32 → SSVF. Для HIP 300 и HIP 350 используется только SSVF. Поиск работает по артикулу и названию.

В карточке два блока — «Данные для подбора» и «Данные для техлиста». Несколько систем можно отметить у одного насоса. Доступны отопление, водоснабжение, канализация, дренаж и подача воды из скважин.

Правки сохраняются в черновик. Кнопка «Опубликовать для подбора» обновляет публичную версию, «Снять с подбора» исключает насос. Публикация доступна администратору и публикующему редактору. Более новый черновик не участвует в публичном расчёте.

## Правила подбора

На `/selection/pumps` доступны быстрый подбор и пустой блок расширенного подбора. До отправки формы результатов нет. Быстрый подбор принимает расход, полный расчётный напор, необязательный статический напор и систему.

Кривая системы — `H(Q) = Hстат + kQ²`, где `k = (Hрасч − Hстат) / Qрасч²`. Пустой Hстат означает ноль; допустимо `0 ≤ Hстат ≤ Hрасч`. При Qрасч = 5 м³/ч, Hрасч = 13 м, Hстат = 2 м получается k = 0,44, расчётная точка остаётся (5; 13).

1. Учитываются только насосы с выбранной системой и пригодной опубликованной кривой.
2. Расчётный расход должен удовлетворять `Qmin < Qрасч ≤ Qmax`.
3. Напор насоса при расчётном расходе должен быть не меньше расчётного.
4. Требуется единственное пересечение кривых насоса и системы в рабочем диапазоне и в пределах исходных точек, с `Qфакт ≥ Qрасч`.
5. Для всех серий действует условие `P2 × K < Pном`, где P2 рассчитана в фактической точке. При Pном до 7,5 кВт включительно K = 1,20, свыше 7,5 до 40 кВт включительно K = 1,15, свыше 40 кВт K = 1,10. Для проверки нужны оба значения мощности.
6. В каждом типоразмере выбираются две разные гидравлические модели с ближайшим достаточным напором. Выводятся все подходящие исполнения этих моделей. Отметка «Оптимальный» не расширяет этот список.
7. Номинальный расход определяется при максимальном КПД. Отметка «Оптимальный» ставится при `0,85 × Qном ≤ Qфакт ≤ 1,20 × Qном`. При отсутствии данных КПД отметка не ставится.
8. В исходном порядке оптимальные варианты идут первыми. Сортировка по столбцам переставляет все строки и сохраняет отметку у каждого насоса.

Ограничение избытка напора не применяется. Интерполяция Q–H, КПД и NPSHr — PCHIP в пределах соответствующих числовых рядов, без продолжения за исходные точки.

## Источники и кривые

Названия, артикулы и исходные точки взяты из «С артикулом HIP.xls»; характеристики и рабочие границы — из каталога с согласованными поправками. Пары столбцов и правила переноса зафиксированы в [формате исходных данных](../../../pump-curve-import-format.md).

Q–H хранится в `curve.points`, КПД и NPSHr — в `pumpSelection.performancePoints`. Пустое значение означает отсутствие отсчёта. Границы рабочего расхода задаются отдельно в `flowMinM3h` и `flowMaxM3h`.

P2 на валу в кВт рассчитывается по формуле `ρ × g × Q × H / (3 600 000 × η)`, где ρ в кг/м³, Q в м³/ч, H в метрах, η — КПД долей единицы. При плотности в кг/л эта формула даёт `Q × H × ρ / (367,098 × η)`. Номинальная мощность двигателя хранится отдельно и сравнивается с P2 в фактической рабочей точке.

Среду и температуру выбирают в форме подбора. Для водного раствора гликоля вводят массовую концентрацию. Studio хранит допуски по среде, температуре и концентрации для каждой карточки. Все карточки участвуют в подборе на воду в пределах указанного в карточке температурного диапазона. По опубликованному допуску для выбранного гликоля поправка HI 9.6.7 применяется автоматически в пределах применимости метода. Напор в форме — в метрах выбранной среды, коэффициент параболы системы определяется по введённой точке.

Для произвольной вязкой жидкости вручную вводят кинематическую вязкость в мм²/с и плотность в кг/м³. Название, температура и концентрация используются в техлисте. Температура и концентрация необязательны.

Во вкладке «График» верхний график содержит Q–H, кривую системы и КПД, нижний — P2 и NPSHr с общей шкалой расхода. Для растворов и произвольной жидкости тонкий пунктир на Q–H и P2 обозначает расходы, при которых P2 превышает номинал двигателя. Во вкладке «Технические данные» отображаются заполненные опубликованные характеристики выбранного насоса. Выбор всей строки таблицы открывает его график.

Клик по Q–H задаёт фактическую точку. Кривая системы начинается с введённого статического напора и заканчивается в выбранной точке. На графике и в PDF при ручном выборе отображается только фактическая точка. Кнопка «Вернуть расчётную точку» восстанавливает предыдущий расчёт.

Кнопка «Скачать техлист PDF» сохраняет текущие условия, результаты, видимые кривые и технические данные выбранного насоса. Графики и таблицы фиксируются на момент нажатия. Скрытие кривой не убирает числовой результат. PDF формируется в браузере; библиотеки загружаются по нажатию, повторного запроса к Studio нет.

## Проверка и перенос

[Фикстура HIP 32](hip32-ssvf-fixture.json) — исторический снимок девяти карточек, только для автономных тестов. Он не описывает текущую базу и не загружается при запуске приложения. Проверять границы расхода, статический напор, выбор двух моделей и их исполнений, отметку оптимальности, сортировку и разделение опубликованных данных и черновиков.

Перед завершением изменений выполнить профильные тесты Vitest, `npm run typecheck`, ESLint затронутых файлов и проверку подбора в браузере. Для интеграционных тестов использовать отдельную БД. Дополнительные требования — в [DEVELOPMENT_RULES.md](DEVELOPMENT_RULES.md).

Разовый перенос данных выполняется временным скриптом вне приложения; после проверки скрипт удаляется. Постоянного загрузчика насосов в проекте нет. Миграции схемы и тестовые фикстуры сохраняются.
