# Payload CMS — подключение и упрощение административной панели

Проверено 26 октября 2026 года. Рабочая ветка: `codex/payload-cms`.

## Что работает

- Payload 3.92.0 и PostgreSQL 17 подключены к существующему Next.js 16.4.2 / React 19 приложению. Публичный сайт и административная панель имеют отдельные layouts.
- Каталог содержит категории, серии и товары с уникальными SKU/внешними идентификаторами, типизированными характеристиками и связями с медиа/документами. Начальные данные: 15 категорий, 20 статей и 3 страницы. Учебные товары в рабочую базу не добавлены.
- Страницы поддерживают блоки, перестановку, скрытие, черновики и авторизованный предпросмотр. Готовые разделы сохраняют существующие анимации и модели. Геометрия, камеры и логика сцены остаются в коде.
- Новые опубликованные товары, категории, статьи и страницы доступны без пересборки. Публикация обновляет поиск и sitemap; переименование сохраняет старые адреса через перенаправления. Снятый с публикации контент посетителю недоступен.
- Роли `admin`, `editor`, `publisher`, `analyst` проверяются сервером. Редактор не может изменить публичную версию через обычную запись, массовое обновление или восстановление версии. Публичная регистрация первого пользователя закрыта.
- CSV/XLSX проходят ограниченный разбор, предварительный просмотр и явный выбор перезаписываемых полей. Импорт транзакционный, повторный запрос идемпотентен, устаревший предпросмотр отклоняется. Импорт сохраняет черновики и не удаляет товары.
- Файлы хранятся вне `public`, черновые файлы защищены. Содержимое уже загруженного файла не заменяется незаметно для опубликованной версии. Для нового файла создаётся новая запись.
- Панель показывает состояние контента и интерфейс импорта. Подготовлены агрегированная статистика Метрики и фиксированные цели без значений формы или поисковых запросов. Аналитика по умолчанию отключена, в административной панели и авторизованном preview не запускается.
- Миграции, повторное начальное заполнение, резервное копирование и проверка восстановления имеют отдельные команды. Начальные записи имеют приватный постоянный идентификатор: повторное заполнение сохраняет переименования и редакторские правки.

## Как пользоваться

Из корня проекта:

```sh
npm run cms:local:init
npm run dev
```

Сайт: `http://localhost:3000`, панель: `http://localhost:3000/admin`.
Локальные данные входа находятся в `.local/admin-access.txt` с правами 0600.
База, секреты, файлы и резервные копии исключены из Git.

## Что требует следующего этапа

Внешний сервер и staging в РФ пока не развёрнуты: необходимы выбранный
провайдер, домен, доступы, PostgreSQL/S3, TLS и VPN/MFA-шлюз. Dockerfile и
Compose подготовлены, но контейнеры на этом компьютере не запускались,
поскольку Docker не установлен. GitHub Actions обновлён в коде; удалённый
запуск CI и публикация из этой ветки не выполнялись.

Для Метрики нужны реальный счётчик и серверный токен чтения. SMTP не настроен:
восстановление пароля по почте намеренно возвращает понятный отказ до создания
токена, а ссылки сброса не выводятся в журнал. Форма заявки остаётся демонстрацией
и не доставляет обращения.

Готовые разделы CMS управляют порядком и видимостью существующего интерфейса;
это не произвольный визуальный редактор всей CSS-разметки. Тексты решений
редактируются обычными полями с сохранением серверной проверки данных. Общие настройки сохраняются
сразу с историей; отдельные draft/publish для них не включены. Удалённые исходные
записи повторный seed восстанавливает — это команда первоначального наполнения,
а не обязательная операция каждого выпуска.

Не выполнялись интеграции 1С, HEISSKRAFT OS и внутреннего ИИ. Корпоративные
закрытые документы в CMS не переносились. Производительность в этой итерации
не оценивалась новой серией лабораторных замеров; функциональные WebGL-тесты
не являются измерением FPS на рабочем устройстве.

## Упрощение Payload: этапы 1–3 плана административной панели

Выполнен отдельный пакет поверх `89cd086`. Puck, новая CMS и ИИ-помощник
в этот пакет не входят. Миграции и формат сохранённых документов не менялись.
До работы сохранены снимки основных экранов в `.local/qa/admin-before` и
резервная копия `.local/backups/backup-2026-10-26T16-48-57-938Z`.
Эта промежуточная копия содержит пустой черновик товара, созданный штатным
открытием формы при проверке; он удалён из рабочей базы. Копия завершённого
предыдущего этапа без него указана выше.

### Изменения интерфейса

- Светлая фирменная оболочка, один набор меню, быстрые действия по ролям,
  последние изменения и черновики. Неподключённая статистика явно обозначена.
- Товар разделён на «Основное», «Изображения», «Характеристики», «Документы»,
  «Проверка». Адрес предлагается из названия и остаётся редактируемым;
  существующие адреса, артикулы и идентификаторы интеграций не переименовываются.
- JSON текстов ЦОД и пожаротушения заменён обычными полями и выбором изображений.
  Сохранён прежний формат, идентификаторы элементов, порядок и серверная валидация.
- Добавлены состояние сохранения, понятная повторная попытка после HTTP-ошибки,
  кнопки черновика и просмотра. В общих настройках явно указано немедленное
  применение изменений. Список страниц показывает адрес и ссылку просмотра.
- Мобильная панель действий переносится на строки. Стили загружаются только
  в layout Payload; публичные страницы, тексты и анимации не переработаны.

### Исправления редакторского процесса

Первый файл сохраняется вручную вместе с байтами: автосохранение медиа отключено,
чтобы Payload не создавал пустую запись до выбора файла. Замена байтов
существующего файла по-прежнему запрещена. У обычных документов штатное
автосохранение сохранено; открытие «Добавить товар» создаёт приватный черновик.

При ошибке сохранения значения остаются в форме, повторная отправка снова
доступна. Чужую блокировку можно увидеть без раскрытия учётной записи сотрудника:
отношение владельца блокировки возвращает только ID. Права чтения пользователей
не расширены. Payload освобождает блокировку после успешного сохранения;
проверка конфликта выполнена во время незавершённой правки.

CMS E2E теперь запускает собственный production-сервер, случайную временную БД,
отдельные загрузки и одноразовые учётные записи. Рабочая БД не используется для
мутаций тестами; после завершения временные ресурсы удаляются. CI использует
тот же запуск. Скриншоты инструкции сняты только в изолированной среде.

### Откат

Отмена только коммита этого пакета возвращает прежний интерфейс Payload;
миграция БД для отката не нужна. Пользовательский контент и файлы не откатываются.
При ручном откате возвращать только исходники, тесты и документацию данного
пакета, сохраняя последующие правки пользователя. Восстановление резервной БД
для отмены оформления не требуется.
